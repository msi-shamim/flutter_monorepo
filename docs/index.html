Production-ready Flutter
monorepos in one command.

Generate a complete Flutter monorepo with your choice of state management, HTTP client, localization, and platforms — fully configured with Material 3 theming, clean architecture, and production linting.

dart pub global activate flutter_monorepo

Why This Tool?

Setting up a Flutter monorepo with proper architecture takes days: configuring workspaces, choosing state management, wiring DI, setting up localization with RTL support, building a design system, writing base classes. This tool does it all in one command.

You pick your stack (GetX or Riverpod? Dio or Chopper?) and get a production-grade monorepo with 5 packages, sealed error handling, Material 3 theming, 12-language support, and 95+ structure checks via the doctor command.

Getting Started

Prerequisites

  • Flutter SDK (stable channel)
  • Dart SDK ^3.10.4

Step 1: Install the CLI

dart pub global activate flutter_monorepo

Step 2: Generate your monorepo

With all defaults (GetX, Dio, English + Arabic):

flutter_monorepo my_app

Step 3: Run the app

cd my_app/my_app_app
flutter run
That's it! With zero flags, you get a complete monorepo with GetX, Dio, English + Arabic localization, Android + iOS platforms, Material 3 theming, and production linting. Everything below is optional customization.

Features

01. State Management

Choose from four battle-tested Flutter state management frameworks. Each generates framework-specific controllers, routing, DI, and screen patterns.

FlagValuesDefault
--state or -sgetx, riverpod, bloc, cubitgetx

GetX (default)

flutter_monorepo my_app --state getx

Generates GetxController with .obs reactive fields, GetView screens, GetPage routing, Binding for DI, and GetStorage persistence.

Riverpod

flutter_monorepo my_app --state riverpod

Generates Notifier with state classes, ConsumerWidget screens, GoRouter routing, provider declarations, and SharedPreferences persistence.

Bloc

flutter_monorepo my_app --state bloc

Generates Bloc with sealed events and states, BlocBuilder screens, GoRouter routing, BlocProvider DI, and HydratedBloc persistence.

Cubit

flutter_monorepo my_app --state cubit

Generates Cubit with direct emit() methods, BlocBuilder screens, GoRouter routing, and HydratedCubit persistence.

02. HTTP Clients

All three clients generate an identical ApiClient API surface with generic methods returning Result<T>.

FlagValuesDefault
--httpdio, http, chopperdio

Dio (default)

flutter_monorepo my_app --http dio

Most popular Flutter HTTP client. Full interceptor support, timeout handling, DioException mapping to AppException.

http

flutter_monorepo my_app --http http

Official Dart team package. Lightweight, minimal dependencies.

Chopper

flutter_monorepo my_app --http chopper

Type-safe HTTP client with interceptor chain pattern.

All clients generate the same methods get<T>(), getList<T>(), post<T>(), put<T>(), delete() — all returning Result<T>. Swapping HTTP clients doesn't change your app code.

03. Localization (12 Languages)

FlagDefault
--locales or -len,ar
# English + Arabic + Spanish + French
flutter_monorepo my_app --locales en,ar,es,fr

12 built-in languages: English, Arabic (RTL), Spanish, French, German, Portuguese, Chinese, Japanese, Korean, Hindi, Turkish, Russian.

Each locale generates an ARB file with 7 pre-translated strings. Includes:

  • Date formatter — short, medium, long, time, custom patterns
  • Number formatter — decimal, currency, compact, percent
  • DirectionalityBuilder — widget for RTL layout support
  • Auto gen-l10n — flutter gen-l10n runs during generation

04. Multi-Platform Support

FlagDefault
--platforms or -pandroid,ios
# All 6 platforms
flutter_monorepo my_app --platforms android,ios,web,linux,macos,windows

Any combination of Android, iOS, Web, Linux, macOS, and Windows. Platform files are generated by flutter create under the hood.

05. Material 3 Design System

Every project includes a complete Material 3 design system in packages/ui/ with light and dark themes.

  • AppColors — Light + dark color schemes
  • AppSpacing — Consistent spacing scale
  • AppTypography — Text styles with Material 3 type scale
  • AppTheme — Complete ThemeData with 30+ component themes (AppBar, Card, Button, Input, Dialog, BottomSheet, Chip, etc.)
  • Responsive utilities — Breakpoints (mobileSmall 360, mobile 600, tablet 900, desktop 1200) with ResponsiveBuilder
  • Asset management — Type-safe AppIcons, AppImages, AppFonts constants

06. Clean Architecture

5 packages following clean architecture principles. The core package has zero dependencies on Flutter or any framework.

PackagePurposeDependencies
packages/coreBusiness logic, models, repositories (interfaces), use casesPure Dart only
packages/uiDesign system, widgets, responsive utilitiesFlutter only
packages/networkHTTP client, interceptors, repository implementationsCore + HTTP client
packages/l10nLocalization, formatters, RTL supportFlutter + intl
my_app_appApp entry point, routing, screens, DIAll packages + state framework

07. Sealed Error Handling

Every project includes a sealed AppException hierarchy and Result<T> pattern.

Exception types

sealed class AppException
├── ApiException (statusCode, endpoint)
├── CacheException (key)
├── ValidationException (field, constraint)
├── NetworkException (isTimeout)
└── TimeoutException (duration)

Result pattern

sealed class Result<T>
├── Success<T>(T data)
└── Failure(AppException error)

All API calls return Result<T>. No uncaught exceptions. Pattern matching with Dart 3 sealed classes.

08. Auto Version Resolution

At generation time, the CLI fetches the latest compatible version of every dependency from pub.dev. If offline, it falls back to tested hardcoded versions.

09. Doctor Command

Validates your monorepo's structure with 95+ checks. Auto-detects your project config (state management, HTTP client, locales) from existing files.

Check structure

flutter_monorepo doctor

Auto-fix missing items

flutter_monorepo doctor --fix

Missing files are restored with full template content — not empty placeholders. Skills, settings, README, LICENSE, and configs are all regenerated.

10. Development Workflow Guides

Step-by-step guides that auto-adapt to your detected state management framework.

flutter_monorepo workflow        # Overview
flutter_monorepo workflow a      # Component Design
flutter_monorepo workflow b      # Screen Design
flutter_monorepo workflow c      # Business Logic

Workflow A — Component Design

Build a reusable widget in packages/ui/ with optional companion state in packages/core/states/. Framework-agnostic.

Workflow B — Screen Design

Build a full screen with controller/provider/bloc + sections pattern. Adapts to GetX (GetxController + GetView), Riverpod (Notifier + ConsumerWidget), Bloc (Events + States + BlocBuilder), or Cubit (emit + BlocBuilder).

Workflow C — Business Logic

Implement business rules in packages/core/, API calls in packages/network/, and wire DI per framework. Pure Dart logic, swappable implementations.

11. Test-During-Development

6 test directories are pre-created so you write tests alongside code, not after:

  • packages/core/test/states/ — Component state unit tests
  • packages/core/test/rules/ — Business logic tests
  • packages/core/test/models/ — Model serialization tests
  • packages/ui/test/widgets/ — Widget render tests
  • packages/network/test/ — HTTP client tests
  • my_app_app/test/screens/ — Screen controller tests

12. AI Agent Skills

Every project includes 4 Claude Code skills in .claude/skills/ that auto-adapt to your framework.

SkillTrigger
Component Design"Build a component", "Create a widget"
Screen Design"Build this screen", "Create a page"
Business Logic"Implement this rule", "Add business logic"
Monorepo Doctor"Check structure", "What's missing"

Pre-approved tools in .claude/settings.json: Read, Glob, Grep, dart analyze, dart test, flutter test, flutter gen-l10n, dart pub get, dart format.

Every project ships with strict, production-grade analysis:

Example Combinations

Default (GetX + Dio + English/Arabic)

flutter_monorepo my_app

Riverpod + All Platforms + 4 Languages

flutter_monorepo my_app \

  --http dio \
  --locales en,ar,es,fr \
  --platforms android,ios,web,macos \
  --license mit \
  --github

Bloc + Chopper + Full i18n

flutter_monorepo my_app \
  --state bloc \
  --http chopper \
  --locales en,ar,es,fr,de,pt,zh,ja,ko,hi,tr,ru \
